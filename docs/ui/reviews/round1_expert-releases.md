## 2. Two-tap reachability for all routes — findings (aspect C)

Route inventory verified against `backend/app/main.py`: **125** route decorators = 10 HTML pages + 3 auth routes + `/health` + **111 JSON endpoints** (REL 30 / SER 24 / DL 42 / OPS 14 + debug 1, as in Part 0). "Every one of the 125 routes … at most two taps" is not a meaningful/testable promise: 111 of them are API endpoints that are invoked by controls, not navigable destinations, and seven have **no UI consumer at all** (deliberate vestigial surfaces): `GET /api/releases/grouped` (REL-041), `GET /api/search` (REL-042 — the palette fixes this one), `GET /api/downloader/queue` (DL-084), `GET /api/series/link-audit` + `POST /api/series/link-repair` (SER-038/039), `GET /api/maintenance/series-aliases` (SER-075), `POST /api/releases/{id}/status` (REL-020). `/auth/callback` and `/health` are not user journeys.

**Amended acceptance target (required):** "Every **user-facing page** (10 HTML pages, auth login/logout when enabled) is reachable from any page in ≤2 interactions on ≤390 px and ≥1280 px; every **user-facing action** is reachable in ≤2 interactions **or** is listed in the gap-disposition ledger as intentionally page-local." Add an explicit table of the 10 pages with desktop path and mobile path (tab or More + item) and verify it in the new suite (source-level assertion of the matrix + manual check).

## 3. Missing requirements (propose as UX-013…, or fold into existing sections)

1. **M1 — Amend non-negotiable #1 / acceptance #5 (route promise).** Replace "all 125 routes" with the page/action wording above; add the API-surface disposition list (REL-041, REL-042, DL-084, SER-038/039, SER-075, REL-020) and state whether each gains an entry (only `/api/search` via palette), stays intentionally internal, or is removed in the redesign. **Blocker if unamended** — the acceptance test as written cannot pass and the matrix overstates reachability.
2. **M2 — Global action dispatcher contract (new UX-013).** One `[data-quick-action]` handler in base.html: action id, owning function, whether it runs in place, busy/disabled rules while a related job runs (sync in progress, feed poll already running returns `started=false`, backfill already running, `downloads:process` foreground), success/error toast copy, and the rule "no page-action `onclick` literals in the palette/sheet markup" (keeps `test_nav_structure.py:147-159`, `:196-198`, `:219` green). This also removes the design's sessionStorage `mt:run` hand-off for all five quick actions (the functions are already global; only modal-opening is needed for backfill).
3. **M3 — Palette search + target-page prefill (new UX-014).** Define `/api/search` result contract for the palette (grouped series/releases, rank order, max 5+5), keyboard/ARIA combobox semantics, no-result state, and **the `/series?q=` / `/releases?q=` prefill behaviour** (templates read `request.query_params`, initialise search, run one server query, set `currentSearch`). Without this, the design's "Enter opens the page with the query" is a no-op: `series_view`/`releases_view` have no query parameters and `releases.html:191` starts empty. Related aspect-E fix: after prefill, the page must not immediately re-run the client-side filter and show "N matches" against an empty DOM (G-15).
4. **M4 — Gap-disposition ledger (new UX-015).** Acceptance #4 demands "every Critical/High gap fixed or explicitly deferred with a reason" but the design contains no ledger. Add the table (G-01…G-50 → fix / defer + reason + device) and make it a reviewed artifact. Known High/Critical gaps **not covered** by the design's page sections and needing an explicit decision: G-08 (styled 404/500/403 — backend/route work, likely defer), G-26 (feed config/edit — fixable frontend-only, see M5), G-38 (logs beyond 150 rows — backend, defer), G-46 (undo for destructive actions — partially frontend, see M6), G-49 (CDN/offline degraded banner — frontend detection + explicit deferral of vendoring), G-50 (first-run onboarding — frontend, see M7), G-40 (dead Settings advanced anchor — actually fixable in Jinja because `debug_actions_enabled` is already in the context, `settings_view`), G-45 (sortable tables — defer), G-47 (URL state for modals/tabs — partial: discovery hash only).
5. **M5 — Feeds config/edit (new UX-016; G-26).** The create API already accepts a `config` object (`schemas.FeedCreateRequest.config`, `POST /api/feeds` `main.py:2038-2051`), but the modal sends only `{url, feed_type}` (`feeds.html:197`) and there is no edit path (`update` does not exist). Frontend-only fix: add the selector/max-pages fields for the `html` type and send `config`; for "edit", prefill the add modal from an existing row and require an explicit "replace (delete + add)" confirmation (or record a deferral). This is the cheapest High-impact fix in the whole design and should not be silently omitted.
6. **M6 — Context continuity for reload-inducing actions (aspect E; new UX-017).** The shell turns most mutations into `location.reload()` (e.g. blacklist/ignore/track/prioritize), so palette-triggered actions from other pages lose the current page, filters, sort, view and scroll. Requirement: (a) prefer in-place/`fetch`+banner paths for global quick actions (UX-013); (b) preserve Releases/Prioritized `status/view/sort/search` + scroll in `sessionStorage` and restore on reload; (c) toasts for destructive actions get an **Undo** where an endpoint exists (`/ignore`↔`/unignore`; blacklist has no id in the POST response, so use a "View blacklist" deep link or defer) — otherwise list as deferred in M4.
7. **M7 — First-run onboarding (new UX-018; G-50).** Add a dashboard onboarding card when `calibre_status.available == false` / `stats.monitored_series == 0` / feeds list empty / downloader never tested, linking to `Settings#section-calibre`, `#section-downloader`, `#section-schedules` (section ids exist: `settings.html:57,79,328`) and `/feeds` Add Feed; include the same three entries in the palette. Data for the Calibre check is already in the dashboard context; feeds/downloader can be added to the existing context (no route behaviour change).
8. **M8 — Admin/ops discoverability (aspect C).** Palette must include the nine Settings deep links as results (ids `settings.html:23-47`) plus "Maintenance"/"Advanced" entries and Logs filters; Settings mobile section chips keep `IntersectionObserver` (design §3.10) and the palette entry must land on the right anchor (`scroll-mt-24` already present at `settings.html:57+`). Also: Settings maintenance risk grouping/collapse and the qBittorrent password echo are outside the current HTML-only scope; the design must either fix (password: only possible safely with backend "blank = unchanged" semantics — a backend change beyond the allowed three, so likely defer with a documented risk) or list them as deferrals (M4).
9. **M9 — Releases filter/search composition (G-14/G-15).** Design §3.3 preserves `sort`/`view` but not the active search; status-pill/view links are still full-page URLs (`releases.html:24-66`) and will drop the search. Preserve `search` as a URL parameter in all pill/view links (or move filters to client-side `replaceState` + refetch) and make "N matches" reflect the paged result set, not loaded DOM.
10. **M10 — Prioritized sort/search (G-20).** The page has no sort control (`prioritized.html:114-120`) and the flat endpoint has no `search`/`sort`/`total` (`main.py:1503-1521`). Fixable portion without backend change: add a sort control wired to `/api/prioritized/cards` (which accepts `sort`) for the grouped view; flat view sort/search must be explicitly deferred or added to the allowed backend-change list (the endpoint would need the same params as `/api/releases/flat_rows`).
11. **M11 — Discovery pending-filter state (G-22/G-25).** Design fixes param preservation and keyboard handling, but not "sort discards unapplied tag chips": sorting immediately navigates (`discovery.html:62-75,567-571`) taking the visible select value, while the picker keeps pending chips. Requirement: either Apply pending chips before navigating, or keep the picker's pending state in `sessionStorage` and restore it after the reload; also make the visible sort the single source of truth (the hidden `tag-sort-mode` exists but is not user-editable).
12. **M12 — Test-contract preservation policy (see §5).** Design §7 lists only four suites; the redesigned shell/pages touch ~10 source-assertion suites. Add a policy: "any pinned string/id/marker either stays byte-identical or its asserting suite is updated in the same change, with the list in the PR/validation log; new suite is additive only."
13. **M13 — Library of global keyboard shortcuts / discoverability follow-up.** Design adds Ctrl/⌘+K and `/` (Releases). Recommend also rendering the shortcuts in the palette footer and/or a palette "Keyboard shortcuts" entry; no new global key handler beyond these two avoids conflicts with browser/AT shortcuts.
