Nyaa / Tracker Source

Base URL used for every Nyaa request: feed polls, polite backfill pagination and .torrent links. Set this to your own mirror/proxy when nyaa.si is unreachable (e.g. DNS-blocked on your network).

Accepts a bare base (https://wemew-nyaa.vercel.app) or a full Nyaa-style URL (https://mirror/?page=rss&c=3_1&f=0); the query string is dropped and the value is normalised to scheme://host[:port][/path]. The proxy must forward Nyaa's query API: RSS ?page=rss&c=3_1&f=0, HTML paging/backfill ?p=N&c=3_1&f=0&s=id&o=desc, and torrents /download/<id>.torrent. With a mirror configured, no code path requires nyaa.si.

Suspicious volume ranges

Finds releases stored with chapter-scale volume bundles (e.g. Vol 205-215) or titles that now parse as chapter-only. Repair clears the phantom volumes, marks them IGNORED and keeps the history; explicit-volume releases are untouched.

False fuzzy series matches

Finds releases stored under a series that the fixed distinctive-head matcher would no longer map (e.g. “The Red Ranger…” false-matched to “Level 0 Demon King…”). Repair re-keys selected rows to their title-parsed series, preserves IGNORED/BLACKLISTED vetoes and recomputes DISCOVERY/REQUESTED.

Light-novel releases

Persisted light-novel releases are hidden from Releases, Discovery, wanted/auto-download and request lists. Detection uses media tags, ebook formats and publisher/imprint patterns (e.g. “[J-Novel Club]”, “[Yen Press]”, “[Seven Seas]” even without a release group). Auditing is read-only; Ignore marks the selected rows IGNORED (keeping history), Delete removes only the database rows — never files on disk. Both require a second click.
