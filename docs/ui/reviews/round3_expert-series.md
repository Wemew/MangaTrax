## Non-blocking corrections (no blockers)

1. **UX-019 DOM order sentence** (`:233-234`): "the banner sits after the setup/pickup banners in DOM order" is not achievable as written with the global shell placement: `#offline-banner` is emitted immediately after `</header>` (`base.html:379`), before `{% block content %}` and therefore before the Dashboard setup/pickup banners (`index.html:41`). Change to a visual-order statement ("above the page's setup/pickup banners") or move the markup; no test or acceptance item depends on the order.
2. **UX-019 failure predicate precision** (`:227-233`): define what a "failure" is. Current base treats any HTTP response as success (calls `mtPollOk()` before checking `res.ok`, `base.html:1306-1307`) and counts any thrown error, including JSON-parse failures, as a failure (`:1315`), without filtering `AbortError`. Either say "fetch rejection (network error)" — then the implementation matches — or check `res.ok` and filter `AbortError` in the counter (`:1685-1691`).
3. **§4 performance note and G-11 ledger** (`:370,:435`): "the series chain may stay but must stop off-screen" and G-11's "no unbounded drain off-screen" are not stated in UX-021 and are not implemented: `fetchNextSeriesRows()` keeps the 60 ms chain running while `has_more`, independent of viewport (`series.html:264-290`). Add an explicit UX-021 sentence plus an off-screen gate, or downgrade the matrix/ledger wording. Classified non-blocking for this sign-off because G-11 is already PARTIAL, no acceptance assertion depends on it, and the design direction is unchanged.
4. **Implementation carry-over (other owners, not design blockers):** six partial icon buttons (§4 nine-item list) and the `test_ui_polish.py` partial scan extension are still pending at this snapshot; the `body.mt-save-open` producer is present in Settings.
