## 2. Blockers (round-1 DESIGN VERDICT reasons)

1. **B1 — UX-013/§3.7 qBittorrent auto-refresh is not implementable as written.** The existing renderers are Torbox-keyed; qBit rows have no `release_id`, the server already emits duplicate `id="torbox-row-"`, and the qBit status payload falls back to Torbox DB rows when unreachable. Apply the engine-specific, hash-keyed, visibility-aware in-place updater and the duplicate-id fix in §1.
2. **B2 — §3.8's 15 s Manual Pickup refresh is a continuity regression** (loses volume edits, inline errors, focus; fights MangaTasks button reattachment). Apply the non-destructive "changed → Refresh" contract or the dirty/focus/task-guarded in-place update.
3. **B3 — §3.8 prefill is presented as a G-36/DL Q1 mitigation but only changes the picker seed**; the match endpoint re-keys releases and cannot change the pickup's series. State the limitation and post-apply copy, and record G-36 as mitigated.
4. **B4 — UX-007/UX-005 overlay spec lacks a concrete layer table/offsets and relies on "bottom-16" and a fixed Load-more that cannot be collision-free at 360 px.** Adopt the fixed offsets, in-flow mobile Load-more, safe-area and `viewport-fit=cover` decisions.
5. **B5 — UX-002/UX-003 nav contract is internally inconsistent and under-specified against the pinned tests** (header buttons 6 vs 7; Downloads trigger markup; missing §6/§7 updates). Resolve the trigger pattern and list the exact test edits.

## 3. Missing requirements (add)

- **M1 (E):** Downloads queue/inventory refresh failure state + Retry (`downloads.html:1157`) and `aria-busy`; the "last refreshed" label (`torbox-updated`) should also reflect failure.
- **M2 (B/E):** State explicitly that neither the 1 s Torbox poll nor the new 10 s qBit refresh may clobber in-flight DOM patches or armed actions — value cells only, controls untouched.
- **M3 (B):** Navigator must include Awaiting and Staging cleanup, be page-ordered, support keyboard/screen-reader use (`aria-current`, focusable chips) and persist the active section in the URL hash.
- **M4 (E):** qBit refresh must not display Torbox fallback rows when the engine is unreachable (guard `live_state_available`/`degraded`).
- **M5 (B):** Card-mode empty rows: the `colspan` "No active downloads…" rows (downloads.html:321-325, 958; staging 1274) must render correctly when `td` is `display:block` — specify a `.mt-table-cards` empty-state rule.
- **M6 (B/E):** Manual Pickup file rows need touch-sized volume inputs/checkboxes and a per-input saving/saved state plus "revert to stored mapping".
- **M7 (E):** Tag modal unsaved-close guard (discard confirmation).
- **M8 (E):** Dirty-flag lifecycle for Settings and the Downloads in-app config panel, including clearing before intentional reloads.
- **M9 (E):** Single live-region contract (one role=status toast container + the existing Tasks `aria-live`) and which events announce, to avoid double announcement.
- **M10 (E):** Offline/degraded banner for failed polls (`navigator.onLine`) so a disconnected phone does not look idle.

## 6. Final verdict

**DESIGN VERDICT: DISAGREE** — 5 blockers (B1–B5 in §2). The direction, visual language and feature-reachability rules are sound and maintainable in inline JS; the qBittorrent-refresh requirement is not implementable as written, the Manual Pickup auto-refresh/prefill create continuity/expectation regressions, and the overlay plus nav-trigger contracts are under-specified against the pinned tests. Applying the concrete amendments in §1 and adding M1–M10 resolves every blocker; no requirement needs to be dropped.
