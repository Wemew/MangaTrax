## 6. Risks

* **R-1 (blocker-linked)** Implementing “6 header buttons” literally would force dropping/merging a control (or hiding one inside the palette) — the test would then pass while UX-002 quietly loses a trigger. Correct to 7.
* **R-2** `_desktop_nav`/`_mobile_menu` are position/marker heuristics; sheet + palette refactors can make tests pass/fail for the wrong reason. Prefer explicit marker comments and update the helpers in the same commit.
* **R-3** Many existing z-50 layers (five in the shell alone) + three z-40 layers: new tab bar/tasks/toasts/sheet will tie-break by DOM order unless a numeric scale lands with the change; expect overlay regressions on mobile until measured.
* **R-4** `role="menu"` without arrow keys is an ARIA conformance fail (4.1.2); it is pre-existing but Downloads becomes a *changed* surface, so the design must either fix or de-scope it deliberately with the test update.
* **R-5** `sessionStorage mt:run` hand-off can fire stale/duplicate actions after reload/back/forward; needs whitelist + one-shot + timestamp and E2E coverage that a hand-off navigates then runs exactly once.
* **R-6** Hand-rolled focus traps (no dependencies) commonly miss Shift+Tab, dynamically rendered palette items, and triggers removed by re-render; centralise the helper and test keyboard loops.
* **R-7** `data-label` card CSS injects pseudo-content that some screen readers announce, duplicating labels; keep column headers or visually-hidden labels and verify with a screen reader; also the table→card conversion is where the pinned `(t.* or 0)` expressions and duplicate-attribute rules are most likely to break.
* **R-8** Tailwind-play-CDN does not compile `@apply` in a plain `<style>`; `.mt-*` classes must be plain CSS (or `<style type="text/tailwindcss">`). Likewise `slate-850` is still undefined — define it in the Tailwind config (merge risk) or, safer, replace the 7 usages with slate-800/900 (no config change).
* **R-9** Moving toasts top-center on mobile can cover the sticky header/search trigger; pick an offset below the header and keep toasts non-interactive except a dismiss button.
* **R-10** iOS: `100vh`/keyboard can hide the sheet input; use `dvh`, internal scroll, and `overscroll-behavior: contain`; safe-area insets only work with `viewport-fit=cover`.
* **R-11** `test_ui_polish` scans *all top-level templates* only; new icon-only controls in `base.html` will fail if `title`/`aria-label` is forgotten — add them to the new test suite.
* **R-12** The design adds a per-page-load `GET /api/torbox/manual-pickups` fetch on every page; harmless but on `none`-auth LAN deployments it is unauthenticated like the rest — no new exposure, just note it in the implementation plan.

## 7. No-new-dependency constraint

**Holds.** All requirements are implementable with the current stack (Jinja2, inline classic JS, Tailwind Play CDN, Lucide CDN): palette/sheet/tab bar are markup + CSS + vanilla JS; `inert`, `role`, `aria-*` and the native `<dialog>`/`<details>` elements are platform features, not dependencies. Two implementation cautions: (a) do not introduce an icon/focus-trap/markdown library; (b) if the `<dialog>` element is used for the palette/sheet, verify the pinned ids/classes and test scans still pass. No build step is introduced by any UX-00x requirement.

## 8. Design verdict

**DESIGN VERDICT: DISAGREE**

The architecture and page-level changes are directionally right, but the following blocking amendments are required before implementation (the §1 table contains the exact wording):

1. **Header-control arithmetic and the test-update matrix are wrong/incomplete.** UX-002 (and acceptance §6.2) says 6 header buttons; with the Downloads dropdown the correct count is **7**. §7 must additionally cover: the Downloads anchor assertion (`test_nav_structure.py:80`), the dropdown loop/children/parent literals (`:81-84,98-127`), the `_desktop_nav` marker comment (`:52`), the `_mobile_menu` markers (`:65-66`), and the `active_page == 'downloads'` literal (`:318-319`).
2. **Nav dropdown ARIA/keyboard contract unresolved.** Changing Downloads into a `role="menu"` dropdown on a *changed* surface requires the ARIA menu keyboard pattern (arrows/Home/End + active descendant) or a deliberate switch to the disclosure pattern with the `role` test updated (`:116-117`); otherwise WCAG 4.1.2 is violated.
3. **Dialog/focus contract is under-specified.** The sheet/palette claim `aria-modal="true"` without `inert`/`aria-hidden` background, initial focus, focus trap, body-scroll lock, Escape ordering and focus restoration to the correct opener is non-conformant; add the shared helper requirement (and include the lightbox).
4. **Safe areas and reflow are not achievable as written.** Add `viewport-fit=cover` (`base.html:5`), `env()` insets, `dvh`, and a 320 px/200 % reflow acceptance criterion.
5. **Contrast/focus-indicator requirements are unquantified and currently fail.** `slate-500` micro-text ≈3.5:1 and white-on-brand-500 hover ≈3.7:1 fail 1.4.3; the alpha rose focus ring must be measured/strengthened on rose surfaces (1.4.11). Publish the token-pair table and a measurement step.
6. **Live-region/error contract (shared with aspect E) is missing.** Specify a persistent `role="status"` region, `role="alert"` for failures, non-auto-dismissing errors with retry, and `aria-busy` skeleton semantics.
7. **Pinned-literal preservation is not stated.** Visibility-aware polling must keep `setInterval(poll, 1500)` and `setInterval(checkCalibreSyncStatus, 3000)`; add an explicit “no pinned literal changes unless listed” requirement (MR-10) covering the full list in §5.
8. **Scope/access-matrix contradictions.** “All 125 routes within two taps” is impossible (111 JSON routes, 14 with no UI caller) — reword to the 10 pages + user actions; and the matrix’s “More sheet (links)” for Poll Feeds contradicts `test_nav_structure.py:284` (“Poll Feeds” string forbidden in the mobile menu) — either drop that label from the sheet or add an intentional test update.
